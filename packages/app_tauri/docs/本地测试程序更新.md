# 本地测试程序更新

整体顺序：起本地后端 → 把客户端更新地址改到本地 → 上传 debug 安装包造测试记录 → 检查更新 → 下载安装 → 复原。

## 1、启动本地后端

```bash
pnpm dev:server
```

后端以 `NODE_ENV=development` 启动（`packages/app_server/package.json` 的 `start` 脚本），默认监听 `http://127.0.0.1:1999`。注意本地接口**没有 `/api` 前缀**，那是线上反向代理加的，本地路由挂在根路径。

## 2、把客户端更新地址改到本地

**桌面端**：修改 `packages/app_tauri/tauri.conf.json` 中 `plugins.updater.endpoints`

本地测试地址：

```json
"endpoints": [
  "http://localhost:1999/app/check/{{target}}/{{current_version}}"
]
```

正式地址：

```json
"endpoints": [
  "https://download.muxidream.cn/api/app/check/{{target}}/{{current_version}}"
]
```

`{{target}}` / `{{current_version}}` 由插件在请求时替换，占位符要保留。`dangerousInsecureTransportProtocol` 已是 `true`，http 端点无需额外配置。改完重启 `pnpm dev:desktop`（配置是编译期嵌入的，只会重编 app crate）。

**安卓端**：模拟器沿用 `packages/app_android/.env.development` 的 `http://10.0.2.2:1999` 即可；真机改成电脑的局域网 IP（同一网段，且系统防火墙放行 1999 入站）。dev 包默认允许明文 http。

## 3、上传 debug 安装包造测试记录

客户端当前版本见 `packages/app_windows/.env` / `packages/app_android/.env` 的 `VITE_APP_VERSION`（与各端 `package.json` 的 `version` 一致，由 `pnpm updateVersion` 维护），测试版本号必须比它高。

先建草稿（目标记录不存在时上传接口会拒绝）：

```bash
curl -X POST "http://127.0.0.1:1999/app/version/info" -H "Content-Type: application/json" -d "{\"platform\":\"windows\",\"architecture\":\"x86_64\",\"version\":\"0.2.0\",\"changelog\":\"本地更新测试\"}"
```

再上传安装包，关键是带 `mode=debug`：

```bash
curl -X POST "http://127.0.0.1:1999/app/release/upload" `
  -F "file=@./xxx-setup.exe" `
  -F "platform=windows" `
  -F "architecture=x86_64" `
  -F "version=0.2.0" `
  -F "signature=<.sig 文件内容>" `
  -F "mode=debug"
```

命中本地调试模式时：

- 不上传云存储，安装包保留在 `packages/app_server/static/app`；
- 响应 `storage` 为 `local`，`download_url` 形如 `http://127.0.0.1:1999/static/app/windows_0.2.0_x86_64.exe`；
- 下载地址的 Host 取自上传请求，所以用局域网 IP 上传就会得到局域网地址（真机测试时用电脑 IP 调用即可）。

`mode` 只认 `debug`，拼错会直接 400；服务端为生产环境时会忽略该值继续上传云存储。

再发布该版本（检查接口只认 `status=1` 且 `publish_time <= 当前时间`，不传 `publish_time` 即用当前时间）：

```bash
curl -X POST "http://127.0.0.1:1999/app/version/status" -H "Content-Type: application/json" -d "{\"platform\":\"windows\",\"architecture\":\"x86_64\",\"version\":\"0.2.0\",\"status\":1}"
```

## 4、检查更新与下载安装

```bash
curl -i "http://127.0.0.1:1999/app/check/windows-x86_64/0.1.9"
```

- 200 + JSON：命中，客户端点「检查更新」应弹出更新对话框；
- 204：没有比当前版本更高的已发布记录；
- 500：记录字段不全，`signature`、`download_url`、`file_size`、`file_hash`、`publish_time`、`changelog` 六项缺一不可。

完整下载安装还要注意：

- **桌面端**：`signature` 必须是与 `tauri.conf.json` 中 `pubkey` 配对的私钥签出的 `.sig` 内容，否则下载完成时校验失败。生成成套产物要用带签名密钥的构建：设置 `TAURI_SIGNING_PRIVATE_KEY`（和 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`），构建后会额外产出 `*-setup.exe.sig`。
- **安卓端**：`file_hash` 必须是安装包的 32 位 MD5，`file_size` 必须与实际字节数完全一致，否则下载或安装会被拦下；真机下载 APK 还需把该局域网 IP 加进 `packages/app_tauri/src/android_apk.rs` 的 `is_allowed_apk_url` 白名单（模拟器的 `10.0.2.2` 已在白名单内）。
- **安卓架构**：检查接口的 `arch` 被硬编码为 `x86_64`（`packages/app_android/src/adapters/updater.ts`），所以草稿记录的 `architecture` 要填 `x86_64`，否则查不到更新。

## 5、复原

- `packages/app_tauri/tauri.conf.json` 的 `endpoints` 改回线上地址；
- `packages/app_android/.env.development` 的 `VITE_APP_BASE_API` 改回原值；
- 测试记录把 `status` 置为 `2`（已下架）或删除，`packages/app_server/static/app` 下的测试安装包按需清理。
